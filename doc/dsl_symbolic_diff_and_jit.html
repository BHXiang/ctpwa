🧠 CTPWA 内部笔记：DSL 符号微分与 JIT 运作机制

本文梳理 ctpwa 中自定义共振态模型的完整链路：用户写下一个表达式（或配置一个内置模型）， 经过 解析 → 符号微分 → 字节码编译，最后在 GPU 上以 解释器 或 JIT 原生代码 两种方式执行。 写于 2026-08。

一、为什么需要这条链路

振幅拟合需要对每个共振态传播子计算 (F, ∂F/∂θ, ∂²F/∂θ²)（θ 为自由参数，最多 16 个）。 两种技术路线：

模板前向自动微分（AD）符号微分 + JIT（本笔记）
导数何时算运行时伴随计算（GPU 编译路径里 Var 模板携带 grad/hess）host 端一次性推导完成，运行时零导数开销
产物模板展开的 SASS字节码段 → NVRTC 原生 SASS
导数正确性机械正确一阶公式手写（教科书式），二阶自动推导
运行时开销每个事件都要伴随计算字节码直译为直线代码，仅剩纯算术

为什么不能只用模板 AD 一条路？因为解释器 evalCustomSeg 是栈式逐指令求值 （每条指令一次 switch 分支 + 栈数组寻址，且 P 个导数段各自重跑一遍），free 参数拟合时占 forward 的 98% 以上。JIT 把字节码直译为直线寄存器代码，交给 NVRTC 编译成原生 SASS —— 编译器得以做 CSE / 死代码消除 / 指令调度，运行时只剩纯算术。

二、总流水线

表达式字符串→ tokenize + 递归下降解析→ AST（Node 树）→ 符号微分 deriv ×(1+P+P(P+1)/2)→ simplify 代数化简→ compileNode 字节码→ aux 段（host 内存）

aux 段随后兵分两路执行：

解释器：evalCustomSeg 逐指令求值（回退路径） ↕ 二选一 JIT：genSegment 栈→直线 C 代码 → NVRTC 编译 → 物化内核 → 读 buffer

模型的两种定义入口殊途同归：Custom DSL（表达式字符串）走解析器； 内置模型（BWR/BW/Flatte/ONE/GS）走 buildModelAST 程序化构建 AST。 两者最终都产出同一种 aux 布局。

三、阶段一：表达式 → AST

3.1 Custom DSL 语法（src/CustomExpr.cu）

3.2 AST 节点类型（include/SymbolicDiff.cuh）

NodeType: Num | Var | Param | Add | Sub | Mul | Div | Pow | Neg | Func | Composite

Composite = 黑盒复合节点（内置模型），不展开为基础运算树：
  MODEL_BREAKUP_Q0  q0 = breakup(m0, md1, md2)
  MODEL_BF         Bf(L, q, q0, d) —— L 为固定常量
  MODEL_BW         BW(m, m0, w0) = 1 / (m0² - m² - i·m0·w0)
  MODEL_BWR        BWR(m, m0, g0, L, q, q0, d) —— 含内部 Bf² 链
  MODEL_FLATTE     Flatte(m, m0, [g_i, (ma,mb)_i]...)
  MODEL_FLATTE_RHO_RE / IM  道 ρ 因子（仅依赖 s=m² 和道质量，导数 0）
  MODEL_ONE        1 + 0i

Composite 是这套架构的核心抽象：前向求值走内联函数（Bf<double>/BW<double>/BWR<double>）， 导数规则在注册表里预注册。这让 BWR 这种结构复杂的模型不会被符号展开成爆炸的表达式树。

4.2 混合导数策略：一阶手写、二阶自动

Composite 的 一阶导数公式由 modelDeriv 注册表手写（src/ResModel.cu，教科书式公式）：

MODEL_BREAKUP_Q0   q0 = sqrt(A·B/(4m0²)),  A = m0²-(m1+m2)²,  B = m0²-(m1-m2)²
  ∂q0/∂m0 = (m0²(A+B) − A·B) / (4·m0³·q0)
  ∂q0/∂m1 = −(s·B + d·A) / (4·m0²·q0),   s = m1+m2, d = m1−m2
  ∂q0/∂m2 = (d·A − s·B) / (4·m0²·q0)

MODEL_BF          Bf = sqrt(N(z0)/N(z)),  z = q·d, z0 = q0·d
  ∂Bf/∂q  = −d·Bf·N′(z) / (2N(z))
  ∂Bf/∂q0 =  d·Bf·N′(z0) / (2N(z0))
  ∂Bf/∂d  = (q/d)·∂Bf/∂q + (q0/d)·∂Bf/∂q0

MODEL_BW          F = x/s + i·y/s,  x = m0²−m², y = m0·g0, s = x²+y²
  商法则：∂Re/∂a = (∂x/∂a·s − x·∂s/∂a)/s²，∂Im 同理

MODEL_BWR         γ = g0·(q/q0)^(2L+1)·(m0/m)·Bf²
  对数微分：γ′/γ = g0′/g0 + (2L+1)(q′/q − q0′/q0) + m0′/m0 − m′/m + 2·Bf′/Bf

注意 q0 的导数不为零：内置模型中 q0 = breakup(m0, md1, md2) 是复合节点，m0 即自由参数 θ_0 （buildModelAST 里 m0_ast = makeParam(0)），因此 ∂q0/∂m0 ≠ 0， 链式法则会把这个偏导继续传进 BWR 的 γ 与 Bf 因子（见上面 q0′/q0 项）。 子粒子质量 md1/md2 的依赖由 getDaughterMassDep（src/AmpGen.cu）判定：

情形Q0MassDepAST 节点导数
config 粒子表有固定质量FixedMassmakeNum(质量)0
子粒子 = 目标共振态自身M0ParammakeParam(0)δ（带导数）
其他（事件质量）EventMassmakeVar(CVAR_MD1/2)0（运行时值）

Custom DSL 里的 q0 也走同一机制（2026-08 修复）：解析器把它展开为 MODEL_BREAKUP_Q0(makeParam(0), CVAR_MD1, CVAR_MD2) —— 标称质量取第一个参数 （与内核运行时 m0_q0 = all_params[param_offset] 一致），∂q0/∂θ₀ 被精确追踪。 注意这里的约定：DSL 的第一个参数必须是标称质量，否则 q0 的语义与运行时不一致。 需要换标称质量时用 q0(x) 函数形式（见 3.1 模型函数表），展开为 MODEL_BREAKUP_Q0(x, CVAR_MD1, CVAR_MD2)。

二阶导不手写：对一阶导数树再调用一次 deriv 递归推导 （deriv(deriv(ast, j), k)）。这是一次踩坑后的设计决策 —— 手写二阶极易出错： 调试记录见 doc/README 与 morefast/dslformula/README.md（q0″ 曾漏掉 −2·q0sq′·v′/v 项； bf″ = bf·(½lnN″ + ¼(lnN′)²) 是加号）。一阶公式独立、稳定，手写可控；二阶交给机器。

为什么一阶手写而不全部自动？若 BWR 的 ∂/∂θ 完全用链式法则展开， γ 的对数微分结构会生成巨大的嵌套表达式树；而手写公式直接给出最简形态。 同时 Composite 节点在 AST 中保持黑盒，simplify 原样穿越，树不会膨胀。

4.3 代数化简 simplify

每棵导数树都过一遍 simplify：0±x→x、x±0→x、 0*x→0、x*1→x、1*x→x、0/x→0、 x/1→x、x^1→x、1^x→1、0^x→0、 −(−x)→x、数值折叠。这是字节码尺寸的主要控制手段 —— 大量导数项 （如对无关参数求导的 δ=0 链）被削减为零。

五、阶段三：字节码编译（aux 布局）

compileNode 把每棵 AST 树后序遍历为指令序列（每指令 3 个 double：op, arg0, arg1）：

opcode含义
COP_PUSH_NUM / VAR / PARAM / I / PI常量 / 变量 / 参数 / 1j / π 入栈
COP_ADD SUB MUL DIV POW NEG复数算术（栈式，先 pop 右操作数）
COP_CALL函数调用，arg0 = CustomFuncId
COP_MODEL内置模型黑盒，arg0 = CompositeId；Flatte 用 arg1 传道数

最终 aux 段布局（compileCustomExpr / buildModelAST 输出一致）：

aux[0]      = P                        # 自由参数数
aux[1]      = n_seg = 1 + P + P(P+1)/2 # 段数
aux[2..]    = 每段: [n_instr, (op,arg0,arg1)×n_instr]
  段 0        = 值 F
  段 1..P     = ∂F/∂θ_j
  段 P+1..    = ∂²F/∂θ_j∂θ_k (j ≤ k，对称填充)
  每段执行输出 2 个 double: (re, im)

段独立的代价：值段与每个导数段各自重算公共子表达式（例如 q0 链在每个段里都算一遍）。 解释器模式下这是浪费；JIT 模式下由编译器的 CSE 处理（各段生成独立代码，段间共享依赖 NVRTC 优化）。

六、阶段四：执行双轨

6.1 解释器（回退路径）

evalCustomSeg（src/CustomExpr.cu）是设备端栈式复数虚拟机：

  • 栈深上限 kStack = 32（超限静默返回 0，调用方走其它分支）
  • 每条指令一次 switch(op) 分发 + 栈数组读写
  • evalCustomAll 依次执行值段 → P 个一阶段 → P(P+1)/2 个二阶段 （compute_2nd=false 时跳过二阶段；d2 按 j≤k 读、对称填充）
  • 复数运算全精度（乘法 ar·br−ai·bi；除法保护 s==0 → 1e-30；log(0) 同理）

6.2 JIT（主力路径，src/JITCustom.cu）

两段式执行结构（整个 JIT 架构的出发点）：

pass-1：JIT 物化内核（NVRTC 编译） 在 (σ, 事件, SL) 网格上算 (F, ∂F/∂θ[, ∂²F/∂θ²]) → device buffer → pass-2：computeCustomAmpsKernel / computeCustomHessianKernel 改读 buffer

为什么不能直接调用：CUDA 不支持跨模块 device 函数指针 —— cuModuleGetFunction 只暴露 __global__ 内核，__device__ 函数无法从其他编译单元调用。 所以 JIT 内核只能"物化"结果到显存，由 pass-2 读取。

6.2.1 代码生成：栈 → 直线寄存器代码（genSegment）

把字节码段翻译成 C 代码的核心技巧是 惰性表达式 + 按需固化：

  • 栈项 StackVal 先保存表达式字符串（不立即生成语句）；
  • popVal 时 materialize：若未固化，生成 double tN_re = <expr>; 声明， 保证每个子表达式至多求值一次（与解释器逐指令求值语义一致）；
  • 每个算术指令生成一行 pushTemp，如复数乘法 → t3_re = (t1_re*t2_re - t1_im*t2_im);；
  • COP_MODEL → 内联公式原文：jitBf / jitQ0 / jitFlatte （BWR 展开为 x/s + i·y/s 直线代码）。

每个 JIT 节点生成一个设备函数：

__device__ __forceinline__ void ctpwa_jit_node_0_grad(JitArgs A, const DeviceMomenta* dm, int evt, int sl, double* out)
{
    const JitNodeFlat& F = A.nodes[0];
    int L = ((const SL*)A.d_slComb)[F.node_idx + sl * A.decayChain_size].L;
    // 运动学: mm, qq, md1_q0/md2_q0（固定质量→共振态参数→事件质量 三级回退）, q0, p1_*/p2_*
    // seg 0: F
    double t0_re = ...; double t0_im = ...; ...
    out[0] = ...; out[1] = ...;
    // seg 1..P: dF[j]
    ...
}

然后组装 ctpwa_jit_grad / ctpwa_jit_full 两个内核：grid (nSL, ⌈nEvents/256⌉)，每线程遍历 σ 拓扑 × 节点，写入 out[slice_base + ((s·nEvents+evt)·nSL + sl)·nvals]。 full 内核只物化 hessian 目标节点（hessian_target），nvals = 2+2P+2P²。

6.2.2 NVRTC 编译与缓存

  • 编译选项：--gpu-architecture=sm_XX（当前 device）+ --std=c++17
  • CUBIN 优先（nvrtc 内部跑 ptxas），失败退 PTX（driver 再 JIT 一次）
  • 进程级二进制缓存：cacheKey = FNV-1a64(aux 全部 double 内容) + SM arch + hessian_target。 同一 aux 内容跨 block 复用编译产物
  • CUmodule 绑定 context → 每 GPU 各自 cuModuleLoadData + cuModuleGetFunction 加载

6.2.3 prep / launch / 读端

环节说明
jitCompileBlockconfig 加载时懒构建（一次）：收集每 block 的节点 specs + aux_list，编译，失败 → enabled=false 整块回退解释器
jitPrepareGrad / Full每 GPU 一次性准备：slice 布局（total = Σ nSigma·nEvents·nSL·nv），缓冲分配（够用复用），构建 grad_slice[decayChain_size]（节点→slice 偏移，-1=解释器）
jitLaunchGrad / Full默认流 cuLaunchKernel —— 与 pass-2 同流，顺序保证物化先于消费
pass-2 读端内核里 B.d_jit_slice[nodeIdx] ≥ 0 && B.d_jit_out → 直接读 buffer（nvals=2+2P），否则回退 evalCustomAll
参数新鲜度陷阱：ready[gpu] 只表示"首次 prep 完成"，不代表参数新鲜。 nEvents/evt_offset 每次调用必须刷新 —— getHessian 按 data/bkg/phsp 分段调用， 各段 nEvents 不同；stale args 会导致 pass-1 用旧尺寸物化、pass-2 读越界 → 垃圾/nan。

七、调用路径

reComputeAmps（NLL / 梯度，每次迭代） → jitPrepareGrad + jitLaunchGrad（物化 F+dF） → computeCustomAmpsKernel 读 buffer
getHessian（computeUnifiedHessian） → jitPrepareFull + jitLaunchFull（只物化 hessian 目标节点，F+dF+d2F） → computeCustomHessianKernel 读 buffer

JIT 节点筛选（src/AmpGen.cu）：排除 Interp（查表不走字节码）、无 aux、 param_count=0（布局不匹配）或 >16 的节点。hessian 目标的 full 变体生成失败时降级为仅 grad （仍加速 fit 主循环，hessian 走解释器）。

十、一句话总结

表达式 → AST → 复数域符号微分（一阶手写、二阶自动）→ 代数化简 → 字节码段； 运行时 解释器逐指令求值，或 JIT 把字节码直译为直线 C 代码经 NVRTC 编译成原生 SASS， 在 (σ, 事件, SL) 网格上物化 (F, dF, d2F) 到显存，消费者内核改读 buffer。 任何一步失败 → 整块回退解释器，数值逐位一致。

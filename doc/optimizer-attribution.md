## 2. 优化器自身开销（housekeeping）

## 4. 最大单项浪费：极少数迭代的线搜索回溯

`FIT_OPT_PROF=1`（新实现，niter=300, no-polish, runs=1）：

```
[pLBFGS-prof] iters=300 evals=677  eval=58.21s (85.98 ms/eval, 96.9%)
                              house=1.83s (6.11 ms/iter, 3.1%)  2.26 eval/iter
[pLBFGS-diag] 线搜索试探分布: 1次×260 2次×10 3次×2 4次×2 5次×1 6次×2 7次×3 16次×1 17次×18 22次×1
[pLBFGS-diag] fallback=0 max_ls打满=0 撞界cap=15 重启=0/0/0/0
```

- **87% 的迭代第 1 次试探就接受**（线搜索本身工作正常）；
- 但 **18 次迭代各试探 17 次**（t 从 1 连续减半 16 次 ≈ 1.5e-5），这 6% 的迭代吃掉 **306/677 = 45% 的求值**；
- 没有任何重启、没有 fallback、max_ls 未打满 → 不是"卡住"，而是**初始步长 t=1 对这些迭代严重过大**。

机理：`d = −H·g` 中各分量量纲差 2~3 个数量级（耦合 O(1) vs 质量 O(10³)），
少数迭代里 `|d|∞` 极大 → t=1 冲出去 → 需要 16 次折半才回到可用区间。

## 5. 结论与下一步候选（按"收益 ÷ 风险"排序）

| # | 改动 | 预期收益 | 风险 | 是否改变收敛点 |
|---|---|---|---|---|
| **1** | **初始步长上限** `t0 = min(1, τ/|d|∞)`（现在只在第 0 轮做了类似处理） | **最多 ~2×**（evals/iter 2.26 → ~1.2） | 低 | 理论上不改变接受条件，仅省试探 |
| 2 | 早停：连续 K 轮改进 < δ（δ=1 或 5）即停 | 20~49%（按生产历史） | 低 | 会牺牲 <δ 的 NLL |
| 3 | phsp 子采样（1.49M → ~0.3M） | ~3×（86 ms → ~20 ms） | **物理/统计决策**，需先量化 ΔNLL | 改变 NLL 定义 |
| 4 | ctpwa 前向 kernel 优化 | 未知 | 高（CUDA 侧） | 否 |
| 5 | 参数对角预条件（缩放） | 未知，可能很大 | 中 | 否（但改变轨迹） |

**推荐先做 #1**：纯优化器改动、不影响物理、可回退、潜在收益最大（~2×），
且与已有诊断直接对应。

## 7. 【重要】测量噪声地板：真实拟合是混沌的

`bench/probe_determinism.py`（真实 config）：

```
同一组参数、getNLL 重复 5 次:  spread = 4.366e-11   (非逐位可复现)
同一组参数、梯度重复 5 次:     max|Δg| ≈ 9e-12
同一初值、projected_lbfgs 跑 3 次 (niter=100):
  rep0 final = -3447.852558   evals=121
  rep1 final = -3445.335634   evals=122
  rep2 final = -3444.654382   evals=122
  rep0 vs rep1 首个差异在第 10 次求值；rep0 vs rep2 在第 6 次
```

根因：ctpwa 前向 NLL 的归约含原子加 → 同一输入也有 ~1e-11 的浮点差；
该扰动经优化器放大，**第 6~10 次求值即分叉**。

后果（基线同代码同 seed，niter=300，6 次重复）：

| 指标 | 范围 | 中位数 |
|---|---|---|
| evals | 484 – 865（1.8×） | 603 |
| fit 时间 | 42.8 – 76.2 s（1.8×） | 53 s |
| 终值 NLL | −3454.3 … −3445.3（9.0） | −3448.5 |

**因此原方案第 5.1 节的判定规则（"时间改善 >10% 算显著"）不可用**——
噪声是 ±80% 时间 / ~9 NLL，远大于待测效应。修正后的协议：

1. **优化器改动先在"确定性代理问题"上筛**（合成目标、n=48、复现真实的分块量纲差、
   无 GPU kernel 噪声）→ 单次可完全复现，能精确判定 evals-to-target 的改善；
2. **真实拟合只用于最终验证**，且必须用系综（≥8 次）+ 中位数，
   或使用对混沌不敏感的量（evals/iter、试探分布、前 50 次求值的 NLL）；
3. 若要做单轨迹 A/B，需要先把 ctpwa 前向归约改为确定性（block 两级归约，去掉全局原子加）
   —— 属独立课题，有性能代价。

## 8. #1（初始步长上限）判定：**否决**

| 实验（niter=300，2 次重复） | evals | fit(s) | NLL | 试探分布 |
|---|---|---|---|---|
| D1 t0cap=0（基线） | 484 / 589 | 42.8 / 52.0 | −3454.3 / −3448.8 | `... 17次×14` |
| D2 t0cap=1 | 619 / 412 | 54.6 / 36.7 | −3446.1 / −3448.8 | `... 10次×12 11次×11` |
| D3 t0cap=0.01 | 332 / 307 | 30.2 / 27.9 | **−3402.5 / −3404.8** | `1次×283 2次×7 3次×6 4次×4` |

- τ=1：把 17 次试探压到 10~11 次，但制造了新的多试探迭代 → **净收益落在噪声内**；
- τ=0.01：彻底压平（evals/iter≈1.0，省 ~40% 时间）→ **NLL 差 45（远超阈值 3）**，因为
  它对**所有**迭代都缩小了首步，损伤了正常迭代的进展。

结论：**否决 #1**（代码保留为默认关闭的 `FIT_OPT_T0CAP`，或后续删除）。

## 9. 慢迭代的真实结构（只读诊断 `[pLBFGS-slow]`）

niter=300 的一次运行里 9/300 次迭代 ≥8 次试探，吃掉 ~45% 求值，分两种形态：

| 形态 | 例子 | 特征 | 含义 |
|---|---|---|---|
| A | it=156,194,198,201,206,211,217 | γ≈1e-5，`\|d\|∞ ≈ \|g\|∞`（2.4e2），t_acc=2^-16=1.5e-5，gtd=-1e4~1e5 | **方向退化成 d≈−g**（曲率信息失效），t=1 荒谬地大 → 折半 16 次，实际位移 ~1e-3 |
| B | it=238,239 | γ≈1e-4，`\|d\|∞`=1e-2 但 gtd=-1.9e-3（几乎正交） | 方向几乎与梯度正交 → Armijo 要求几乎为零的下降，靠噪声勉强满足 |

**共同点：这些迭代几乎不产生进展，却按最坏情况付 17~19 次求值。**
现有"停滞"判据（`step_inf<=0`、`df<=1e-12·|f|`）都抓不到它们
（step_inf=3.6e-3>0；df 比 1e-12·3450≈3.5e-9 大）。

**下一步候选（#6）**：加入"退化步 → 清空曲率历史重启"判据
（接受步 t_acc 或位移 |t·d|∞ 低于阈值即视为退化），
直接针对这 45% 的浪费；实现后先在确定性代理上筛选，再在真实拟合上做系综验证。

## 10. 确定性代理（`bench/surrogate.npz` + `surrogate_bench.py`）

真实拟合的 1e-11 混沌让单轨迹 A/B 失效，因此从真实问题导出**二次代理**：
在 `solve2/results/best_params.pt` 处取一次 `getHessian`（0.54 s），
用 `f(x)=0.5(x−x0)ᵀH(x−x0)+g0ᵀ(x−x0)` 作为筛选台。

- 忠实度：`f(x0)=−3464.983073`（= 生产最佳 NLL）；H 对角 6.8e1–2.9e5，
  含一个负本征值（与真实"非正定"状态一致）；盒约束与真实一致（含 lo==hi 固定参数）。
- **逐位可复现**（同配置跑 2 次结果完全相同），300 轮只要 **123 ms**。
- 它成功复现了真实问题的病态：大量 17–19 次试探的迭代，
  `|d|∞ = |g|∞`（方向退化成 −g）、γ≈5e-6、t_acc=2^-17。
- 局限：二次代理只能筛**成本**（evals / evals-per-iter），判不了**质量**——
  质量必须在真实问题上用系综（≥6 次）验证。

## 13. phsp 子采样：攻"86 ms 求值成本"本身

工具：`bench/make_phsp_subset.py`（**按整事件**抽样——dat 是"一行一个粒子四动量，
每 `len(Data.order)`=3 行一个事件"）、`bench/probe_nll_points.py`、`bench/f4/`、`bench/f10/`。

同一组 6 个参数点（生产最佳解 + 5 个确定性扰动点）上的 NLL：

| 点 | 全样本 257k | 25%（64k） | 10%（26k） |
|---|---|---|---|
| 0 | −3464.983 | −3480.410 | −3460.941 |
| 1 | −3448.687 | −3463.955 | −3439.529 |
| 3 | −3458.883 | −3474.664 | −3457.577 |
| 5 | −3450.303 | −3464.951 | −3452.230 |
| **单次求值** | **84.9 ms** | **28.8 ms（2.95×）** | **17.4 ms（4.9×）** |

| | 25% | 10% |
|---|---|---|
| 绝对偏移 full−sub（mean±std） | +14.85 ± 0.69 | −4.65 ± 4.38 |
| **形状偏差**（相对最佳点的差值，rms / max） | **0.90 / 1.52** | 4.42 / 6.92 |

**判据**：只有 NLL *差值* 对优化有意义，绝对偏移无害（不同样本的 NLL 不可直接互比）。
形状偏差 0.90 rms ≪ 显著性阈值 3，也 ≪ 系综混沌 9 → **25% 可用于探索**；
10% 的 4.42 已越过阈值 → 不可用。

端到端（各自目录内跑，niter=50, no-polish）：

| | 全样本 | 25% |
|---|---|---|
| phsp 事件 | 257,130 | 64,283 |
| ms/eval | 87.5 | **32.5** |
| house ms/iter | 14.5 | 13.7（**不随子样本缩小**） |
| fit(s) | 5.30 | **2.36（2.25×）** |
| Hessian(s) | 0.45 | 0.21 |
| NLL | −3372.05 | −3395.87（绝对偏移，正常） |

**副作用**：eval 变便宜后 housekeeping 占比从 3% 升到 **29%**——
在这个档位，我上一轮的 two-loop 改动从"值 2%"变成"值 ~10%"。

### 成本模型的标定

拟合 `ms/eval = a + b·N_phsp`（三个样本点）：`a ≈ 9.8 ms`（data+bkg 项 + 固定开销），
`b ≈ 0.29 µs/事件`。即 **phsp 项占一次求值的 88%**，data 项只占 ~9%。

### 一个真实陷阱（已发现，未修）

`fit.py` 的 `ana = ctpwa.analysis()` 在**模块导入期**执行，早于 `main()` 解析 `--config`，
所以 **`--config` 指定的文件并不用于构建分析**——它只影响 `chdir`。
必须让 **cwd 下的 `config.yml`** 就是想要的配置（这也是 auto_pwa 迭代目录的既有约定）。
修法（建议，未实施）：把分析构建移入 `main()`，用 `ctpwa.analysis(config_path)`。

## 14. f4（25% phsp 子样本）确认性验证：**否决**

两次独立的 f4（64,283 事件）拟合——盲跑（seed 42, niter=1000）与从生产最优
warm-start（niter=300）——**收敛到同一个 f4 极小**（f4-NLL −3487.565576 vs
−3487.565590，差 1.4e-5）。把该点代回**全样本**：

| | 全样本 NLL |
|---|---|
| A = 生产全样本最优 (`solve2/results/best_params.pt`) | **−3464.9831** |
| B = f4 拟合（盲跑） | −3458.0655 |
| B′ = f4 拟合（warm-start） | −3458.0660 |
| **ΔNLL(A→B)** | **+6.92**（阈值 3） |

参数位移：共振态参数多在 free_range 宽度的 0.06%–6.8%，但
**耦合块 max|Δ| = 1.2715 vs |A|∞ = 2.6185 → 48.6%**，且 `phi1680_width`
从 0.146 被推到上界 0.188（钉住）。即**子样本把拟合推到了另一支解**，
不是数值噪声。

**物理解释**：phsp/data = 257,130/25,668 ≈ **10:1**（全样本）；25% 后降到
64,283/25,668 ≈ **2.5:1**。MC 诱导偏置的经验判据是 N_MC/N_data ≳ 5–10，
2.5:1 已不足 → f4 的 2.95× 是**有偏**的，不可用。

（§13 里 6 点探针给出的"形状偏差 0.90 rms"只覆盖了 A 附近的局部区域，
低估了全局位移——这正是为什么**必须做拟合级验证**，不能只看点位探针。）

**结论**：单次求值 86 ms 不能靠抽样降下来。要再快只能动 ctpwa 前向 kernel
本身（0.33 µs/事件 × 29 波）。

**方法论结论（最重要的一条）**：本分析的前向 NLL 逐位不可复现（原子加 → 1e-11
抖动），拟合是混沌的（第 6–10 次求值分叉，同代码同 seed 的 niter=300 终值散布
~9 NLL、耗时散布 1.8×）。因此：
1. 任何"单次跑看起来更快/更好"都不能作为依据（本次两个假阳性都是这么来的）；
2. 优化器改动先用**确定性代理**（§10）筛成本，再用**真实系综 ≥6 次**验质量；
3. 判定阈值必须是 ΔNLL > 3（或 BIC），不能是"感觉更快"。

📦 CTPWA 发布笔记：GitHub + PyPI 自动化

本文记录如何用 GitHub Actions 自动构建 manylinux wheel 并发布到 PyPI， 以及遇到问题时的排查思路。写于 2026-08（CUDA 13.2 / torch 2.12 / Python 3.12）。

一、总体流程

git tag v0.3.0→ push tag 到 GitHub→ Actions 自动构建 wheel→ 自动上传 PyPI→ pip install ctpwa

发布一个版本只需要两条命令：

git tag v0.3.1 && git push origin v0.3.1

二、GitHub 基础

2.1 分支

分支用途说明
main发布GitHub 默认分支，workflow 必须在这里才能被 tag 触发
opt-code开发日常开发分支，测试通过后合并到 main

2.2 常用命令

git status                    # 查看改动
git add -A && git commit -m "描述"
git push origin main          # 推送到 GitHub
git tag v0.3.1                # 打 tag
git push origin v0.3.1        # 推送 tag（触发 CI）
git tag -f v0.3.0             # 强制重打 tag（重跑 CI 用，需配合 force push）
git push origin v0.3.0 --force
⚠️ 注意：仓库 .gitignore 第一行是 *（忽略一切）， 新文件必须加白名单（!目录/）才会被 git 跟踪。改过 gitignore 后记得 git add -A 确认新文件真的进去了。

三、GitHub Actions 配置

3.1 workflow 文件

文件位置：.github/workflows/build-wheel.yml

on:
  push:
    tags: ["v*"]        # 推 tag 时触发
  workflow_dispatch:    # 网页上手动触发（Actions 页面 → Run workflow）

3.2 Secrets（敏感信息）

PyPI 的 API token 存在 GitHub Secrets，CI 里用 ${{ secrets.PYPI_API_TOKEN }} 引用：

GitHub 网页 → Settings → Secrets and variables → Actions → New repository secret
Name:  PYPI_API_TOKEN
Value: pypi-xxxx（PyPI 生成的 token）

四、CI 构建步骤详解

构建在 ubuntu-22.04 runner 上直接进行（不用容器），产物是 manylinux_2_34/2_35 双兼容 wheel。各步骤作用：

步骤做什么关键点
checkout拉取代码—
setup-minicondaPython 3.12 环境wheel 标签是 cp312
Install CUDA 13.2apt 装 nvcc + cublasNVIDIA keyring + sudo；runner 默认非 root！
Install ROOTconda install -c conda-forge rootUbuntu 22.04 没有 ROOT 的 apt 包
Install torchpip install torch==2.12.0+cu132必须与 CUDA 版本匹配
Build wheelsetup.py bdist_wheelenv 里必须设 TORCH_CUDA_ARCH_LIST（见 §6 坑4）
auditwheel repair打 manylinux 标签 + 排除第三方库exclude ROOT/CUDA/torch（用户机器自备）
Publish to PyPI上传 wheel 到 pypi.org用 secrets.PYPI_API_TOKEN

4.1 GPU 架构（gencode）

wheel 内置 7 个 SASS 变体，覆盖 RTX 20 系到 50 系 + A100/H100：

TORCH_CUDA_ARCH_LIST: "7.5 8.0 8.6 8.9 9.0 10.0 12.0"
# sm_75 / sm_80 / sm_86 / sm_89 / sm_90 / sm_100 / sm_120

验证 wheel 里的架构：

unzip -q ctpwa-0.3.0-....whl && cuobjdump --list-elf ctpwa.so

五、PyPI 配置

5.1 API token

pypi.org → Account settings → API tokens → Add API token
建议 Scope 选 "Project: ctpwa"（只授权本项目，比全账户 token 安全）

5.2 手动上传（不用 CI 时）

pip install twine
python setup.py sdist                        # 打源码包
twine upload dist/*                          # 上传（读 ~/.pypirc 的 token）

5.3 sdist vs wheel

类型内容安装适用
sdist（.tar.gz）源码现场编译（需 nvcc/ROOT/yaml-cpp）老系统、特殊 GPU
wheel（.whl）编译好的 .so免编译主流系统（glibc ≥ 2.34）
⚠️ PyPI 规则：
  • 同一个版本可以追加不同文件（sdist + wheel 共存），但不能覆盖或删除已上传的文件——发错了只能升版本号！
  • PyPI 只接受 manylinux 标签的二进制 wheel，linux_x86_64 会被 400 拒绝。

六、故障排查表（踩过的坑）

症状原因修复
dpkg: command not found manylinux_2_34 容器是 RHEL 系（AlmaLinux），没有 apt/dpkg 不用容器，直接用 ubuntu-22.04 runner 编译（glibc 2.35 → manylinux_2_35）
dpkg: requested operation requires superuser privilege GitHub runner 默认用户是 runner（非 root） apt/dpkg 命令加 sudo
Unable to locate package libroot-dev Ubuntu 22.04 移除了 ROOT 的 apt 包 conda install -c conda-forge root（6.28+）
IndexError: list index out of range（torch cpp_extension） runner 无 GPU，torch 检测不到 CUDA 架构 → arch_list 空 env 设 TORCH_CUDA_ARCH_LIST: "7.5 8.0 ... 12.0"
400 Binary wheel has an unsupported platform tag 'linux_x86_64' PyPI 只收 manylinux 标签 auditwheel repair 打 manylinux 标签
cannot repair ... too-recent versioned symbols 本机 glibc 2.43，符号太新（auditwheel 上限 2_41） 不要在本地发 wheel，用 CI（runner glibc 2.35）构建
跑出奇怪性能（如 Hessian 慢 27×） 增量编译不跟踪 #include 依赖，链接了新旧混合的 .so setup.py 的 ForceBuildExtension 每次强制全量重编

6.1 排查 CI 失败的流程

  1. GitHub 网页 → Actions → 点失败的 run → 点红色步骤 → 看最后几行
  2. 先看是 哪一步失败（CUDA/ROOT/torch/Build/Publish），再对症下药
  3. 修完 workflow → 重新打 tag 触发：git tag -f v0.3.0 && git push origin v0.3.0 --force
  4. 构建很快失败（<2 分钟）= 环境/配置问题；跑到 Build 步骤（10+ 分钟）= 编译问题

七、安装指引（目标机器）

# 1. 系统依赖（wheel 不打包这些，目标机器必须自备）
#    - CUDA 13.2 runtime（libcudart.so.13 / libcublas.so.13）
#    - ROOT 6.26+（source thisroot.sh）
#    - yaml-cpp
sudo apt install libyaml-cpp-dev

# 2. torch（必须与 CUDA 匹配）
pip install torch==2.12.0+cu132 --index-url https://download.pytorch.org/whl/cu132

# 3. ctpwa（免编译）
pip install ctpwa

# 验证
python -c "import ctpwa; a = ctpwa.analysis('config.yml'); print(a.getNVector())"
💡 兼容性要求：manylinux_2_34/2_35 wheel 需要目标系统 glibc ≥ 2.34 （Ubuntu 22.04+、Debian 12+）。老系统（如 Ubuntu 20.04）请装 sdist 源码编译。

八、本地构建 wheel（排查/备用）

bash scripts/build_wheel.sh          # 构建 + auditwheel
# 环境变量可覆盖:
#   MANYLINUX_PLAT=...               # 平台标签（默认 manylinux_2_34）
#   TORCH_CUDA_ARCH_LIST="7.5 8.0"   # 架构列表

注意：本地构建的 wheel 若想上传 PyPI，需本机 glibc 符号 ≤ 2.41（本机 2.43 会失败）—— 所以日常发布统一走 CI。

九、常用速查

# 发布新版本
git tag v0.3.1 && git push origin v0.3.1
